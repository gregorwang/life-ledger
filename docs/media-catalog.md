# Media catalog and seasons

Migration `0005_media_catalog_and_seasons.sql` adds:

- `screen` as a media and entry type. Movies and TV series remain in this
  single category and may use `media_kind = 'movie' | 'tv'`.
- nullable `watch_status` and nullable work-level scores on `media_works`.
- `media_seasons`, with nullable season score and watch status.
- nullable `media_logs.season_id`. Existing `season_label` remains for
  backwards compatibility and historical display.

The migration rebuilds the checked `entries` and `media_works` tables. Before
dropping either parent, it copies `media_logs` and `entry_revisions` into
constraint-free migration tables; it then recreates the child tables, indexes,
privacy triggers, and foreign keys. This prevents parent table replacement from
triggering `ON DELETE CASCADE` on historical rows.

## Core RPC

- `listMediaWorks(input)` filters by `mediaType`, `mediaKind`, `watchStatus`,
  and text query.
- `getMediaWork(id)`, `createMediaWork(input)`, `updateMediaWork(id, input)`,
  and `deleteMediaWork(id)` manage works.
- `listSeasons(mediaWorkId)`, `createSeason(mediaWorkId, input)`,
  `updateSeason(id, input)`, and `deleteSeason(id)` manage seasons.
- Existing `listAnime`, `getAnime`, and `logMedia` remain available.
  `logMedia` additionally accepts `mediaType: "screen"`, nullable
  `mediaKind: "movie" | "tv"`, and nullable `seasonId`.

Scores remain optional. A media log may only include a score when
`ratingScope` is explicit. `episodeLabel` is only accepted with
`ratingScope: "episode"`; an episode score is never generated by default.

## Production seed

`scripts/seed/owner-anime-catalog.sql` contains 27 idempotent anime work rows
and 23 neutral season catalog rows. Work scores, season scores, and
season-level watch assertions are all `NULL`. Work-level watch status is
`completed`, with legacy `progress_state = 'watched'`.

The seed resolves season parent IDs by `(user_id, media_type,
normalized_title)`, so it also works when a matching work already exists under
a non-seed ID. It uses the downloaded cover convention
`/assets/anime-covers/<slug>.jpg`.

After reviewing a remote backup, apply and seed explicitly:

```powershell
pnpm exec wrangler d1 migrations apply life-ledger-prod --remote --config services/core/wrangler.jsonc
pnpm exec wrangler d1 execute life-ledger-prod --remote --config services/core/wrangler.jsonc --file scripts/seed/owner-anime-catalog.sql
```

The seed is deliberately separate from migrations so applying schema changes
does not silently insert personal catalog data.
